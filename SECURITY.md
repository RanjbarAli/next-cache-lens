# Security policy

## Supported versions

Until the first stable release, security fixes are applied to the latest published 0.x version.

## Reporting

Please use GitHub's private vulnerability reporting feature on the repository's **Security** tab when it is enabled. If private reporting is unavailable, open a minimal issue asking a maintainer to establish a private channel; do not include exploit details or secrets in a public issue.

Include the package, Next.js, and Node.js versions, affected boundary, impact, and a sanitized reproduction. Never include real cookies, authorization headers, cached values, credentials, or user data.

Maintainers will acknowledge a complete report, investigate it, and coordinate disclosure after a fix is available. This document intentionally does not invent an unmonitored security email address.
